# Repository notes

- The shipped Electron app starts in `main.js`, which loads `index.html`. Most UI, tournament logic, and Vue state live in that one HTML file (inline module script); there is no `src/` build pipeline. `login.html` is a separate Firebase/CDN-based page, not the Electron entrypoint. `experimentals/` contains alternate/older HTML versions; do not treat them as the active app.
- `index.html` imports Vue from `./node_modules/` and loads local fonts/icons; install dependencies before previewing it. `npm start` builds CSS first, then starts Electron. For a browser-only UI check, run `npm run build:css` and serve the repository root over localhost (for example, `python -m http.server 4173 --bind 127.0.0.1`); do not open the HTML as a bare file URL.
- Edit `input.css` for custom/Tailwind styles. `css/output.css` is generated **and tracked**; regenerate it with `npm run build:css` after changing `input.css` or Tailwind classes in `index.html`. Tailwind scans only `index.html` and `main.js`, not `login.html`.
- Focused verification: `npm run build:css`; `npm run make` builds CSS and packages via Electron Forge. `npm test` is a failing placeholder, and there are no configured lint/typecheck/test suites. `npm run dist` invokes `electron-builder`, which is not listed in the dependencies; use the Forge commands instead.
- The active page persists events, competitors, brackets, and keyboard settings in `localStorage`; scoreboard popup state is synchronized via `BroadcastChannel('karate_manager_sync')`. Query parameters select `?view=scoreboard`, `?view=judge&judgeId=...`, or pre-registration via `?eventId=...`. `initJudgeListener` is currently empty; do not assume judge synchronization is implemented.
- `firebase.json` deploys the repository root (`public: "./"`) and ignores only Firebase config, dotfiles, and `node_modules`; review what would be published before any hosting deploy. The repository is private and `LICENSE.md` contains this version's terms; the `ISC` field in `package.json` does not match it.
